# ロールバック

```sh
sekai --store ./sekai-store rollback ./world 1
sekai --store ./sekai-store rollback ./world @stable --in overworld
```

指定したスナップショットからワールドを再構築し、リージョンファイルをアトミックに上書きします（同一ディレクトリ内に一時ファイルを作成し、`fsync` を実行した後に `rename` で置き換えるため、既存ファイルがインプレースで破損することはありません）。スナップショットの引数には `<id>` または `@tag` を指定できます（詳細は[タグ](tags.md)を参照）。復元されたファイルにはスナップショット取得時のタイムスタンプが付与され、`LastUpdate` などの揮発性タグもキャプチャ時の値へと巻き戻されます。

デフォルトのロールバックポリシーは厳格（安全重視）に設定されています：

- スナップショットに含まれない（バックアップ以降に新しく作成された）リージョンファイルは削除されます。
- スナップショットに含まれないチャンクは再構築時に破棄されます。
- ツームストーンが記録された（削除済みの）チャンクは削除されます（リージョン内のすべてのチャンクがツームストーンの場合はファイル自体が削除され、ヘッダーのみの空ファイルが残ることはありません）。
- CAS 内に存在しない Blob がある場合はエラーを報告して即座に中断します（データ破損と判断されます。不完全なワールドを中途半端に書き戻すより、処理を中止する方が安全なためです）。

これらの挙動は、以下のオプションで柔軟にカスタマイズできます：

| フラグ | 効果 |
|---|---|
| `--keep-post-snapshot-files` | スナップショット作成後に追加されたリージョンファイルを削除せず保持する |
| `--keep-post-snapshot-chunks` | 再構築対象のリージョン内にある、スナップショット作成後に追加されたチャンクの実データを保持する |
| `--keep-tombstoned-chunks` | ツームストーンが記録されたチャンクの実データを保持する（全チャンクがツームストーンのファイルも削除されず残る） |
| `--on-missing-blob skip-chunk` | Blob が欠損しているチャンクをスキップして処理を継続する（デフォルトは `abort`） |
| `--on-missing-file derived-only\|error` | 配置先を推測する代わりに、兄弟フォルダの探索を無視するか、エラーとして終了する（デフォルトは `sibling-first`） |

- スコープフラグ（`--in`, `--region`, `--kind`）: 指定したスコープ内のみを再構築および削除の対象とします。詳細は[スコープ（対象範囲）の選択](../scope.md)を参照してください。通常通り `--timing` や `--json` と組み合わせることが可能です。
- 再構築の開始前に、CLI は対象スナップショット・スコープ・ポリシーの設定内容を標準エラー出力に表示します（通常テキスト出力時のみ）。
