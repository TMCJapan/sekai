# チェックアウト

```sh
sekai checkout experiment                  # ブランチに切り替える
sekai checkout v1                          # コミットで HEAD を detach する
sekai checkout main~2 --in overworld       # 範囲を復元する（HEAD は動かない）
sekai checkout -f                          # コミットしていない変更を捨てる
```

`checkout` は、Git と同じように HEAD を切り替えるか、ワールドの一部を復元します。

- ブランチを指定すると、HEAD をそのブランチに付けます（`Switched to branch 'experiment'`）。別のワークツリーでチェックアウトされているブランチは拒否されます。
- タグ、コミット ID、`main~2` などそれ以外の commit-ish を指定すると、HEAD を detach します。HEAD がブランチを離れるときは、Git の detached HEAD の案内を表示します。
- 範囲指定（`--in`、`--region`、`--kind`、`--scope`）があるときは、その範囲だけを commit-ish（省略時は HEAD）から書き直します。HEAD は動きません。
- 引数なしの `checkout` は何も変えません。`checkout -f` はワールド全体を HEAD から再構築します。どちらも、まだコミットのないブランチでは失敗します。

ワールドは、HEAD を動かす前に対象のコミットから再構築されます。リージョンファイルはアトミックに書き換えられます（対象ディレクトリ内の一時ファイル + `fsync` + `rename`。その場での書き換えは行いません）。HEAD のコミットと対象のコミットで内容が一致するリージョンファイルには手を付けないため、そのファイルのコミットしていない変更はそのまま残ります。

## コミットしていない変更

`-f` を指定しない場合、HEAD のコミット以降に追加・変更されたチャンクを失うことになるときは、何も書き換える前に拒否します。

```text
error: your local changes to 2 region files would be overwritten by checkout
```

先にコミットするか、`-f` を指定して変更を捨ててください。HEAD 以降に削除されたチャンクは、復元しても何も失わないため対象になりません。

## 復元ポリシー

デフォルトのポリシーは厳格です。

- コミットに存在しないリージョンファイルは削除されます。
- コミットに存在しないチャンクは再構築時に消えます。
- ツームストーンのチャンクは削除されます（すべてのチャンクがツームストーンのリージョンはファイルごと削除し、ヘッダーだけのファイルは残しません）。
- CAS に Blob がない場合は明確に中断します（データ破損です。不完全なワールドは、ないよりも悪い結果になります）。

それぞれの動作は、デフォルトを変えずに設定できます。

| フラグ | 効果 |
|---|---|
| `--keep-post-commit-files` | コミットに存在しないファイルを削除せずに残す |
| `--keep-post-commit-chunks` | 再構築するリージョン内の、コミットに存在しないチャンクの現在のデータを残す |
| `--keep-tombstoned-chunks` | ツームストーンのチャンクの現在のデータを残す。すべてツームストーンのファイルには手を付けない |
| `--on-missing-blob skip-chunk` | Blob がないチャンクを飛ばす（デフォルトは `abort`） |
| `--on-missing-file derived-only\|error` | 場所を推測せず、兄弟フォルダを無視するか失敗する（デフォルトは `sibling-first`） |

- `-j`/`--jobs N` で同時に再構築するファイル数を指定します（`0` は CPU ごとに1つ）。
- スコープ指定があると、スコープ内だけを再構築・削除します。[スコープの選択](../scope.md)を参照してください。`--timing`/`--json` も通常どおり併用できます。
