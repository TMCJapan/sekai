# コミット

```sh
sekai commit
```

ワールドを HEAD 上の新しいコミットとして記録します。Git と同じく、まず `[main (root-commit) <id>]`、`[main <id>]`、`[detached HEAD <id>]` のいずれかの要約行を表示し、続いてチャンク数・Blob 数・ツームストーン数を表示します。まったく同じ内容のコミットを再度記録しても、行を追加せずに既存のハッシュを返します。

記録の前に、ワールド全体に対して `cache update` と同じ処理を実行し、リージョンイメージキャッシュを温めます。これにより、`diff` と `status` はすぐに変更のないリージョンを証明できます（[キャッシュ](cache.md)を参照）。`--timing` を指定すると、`cache_ms` がこの処理の時間を、合計時間が両方の処理を表します。`--no-cache` を指定するとこの処理を省略します。

- `-j`/`--jobs N` で両方の処理のワーカー数を指定します（`0` は CPU ごとに1つ）。
- 進捗は標準エラー出力が端末のときに表示されます。`--no-progress` で止められ、`--json` のときは表示されません。
- スコープ指定（`--in`、`--region`、`--kind`）で記録する範囲を限定できます。[スコープの選択](../scope.md)を参照してください。
- 上記の内容を書き込まずに確認するには、[検証・検査](inspection.md)の `status` を参照してください。
- コミットにはメッセージがないため、`-m` はありません。

コミットのたびに、スコープ内のすべてのリージョンファイルを読み込みます。変化のないチャンクはフォールバックで解決されるため、新しい Blob も履歴の行も増えません。変更のないコミットでも、コミットの行は1つ書き込まれます。
