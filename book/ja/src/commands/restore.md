# リストア

```sh
sekai restore ./world --in overworld:-8,-8..7,7
sekai restore ./world --source HEAD~1 --scope spawn
sekai restore ./world -s main --overlay --region overworld:0,0
```

指定した範囲だけをソースコミットの状態へ復元する、sekai 版 `git restore` です。[チェックアウト](checkout.md)がコミットを明示してワールド全体（または選択範囲）を再構築するのに対し、リストアは日常的なホットリカバリのためのコマンドです。現在のワールドが乗っているコミットをわざわざ指定せずに、特定範囲のローカルな破壊（荒らしなど）を元に戻せます。コミットの記録や ref の移動は一切行わず、リージョンファイルはチェックアウトと同様にキャプチャ済みのペイロードからアトミックに再構築されます。

## ソースと選択範囲

- 選択範囲は git の pathspec に相当し、**必須**です。`--in` / `--region` で領域を指定するか、`--scope` で保存済みのスコープを名前で指定します（[スコープ（対象範囲）の選択](../scope.md)を参照）。`sekai restore ./world` のように範囲を指定しない場合や、`--kind` のみの指定（種別を絞るだけでパスを指定しないため）は `you must specify path(s) to restore` で失敗します。ワールド全体の再構築はチェックアウトの役割です。
- `--source <rev>` / `-s <rev>` で復元元を指定します。指定できるリビジョンはチェックアウトと同じです（コミットハッシュ、ref 名、`HEAD` / `@`、後ろに `~<n>` を 1 つ）。省略時のデフォルトはアクティブな ref のターゲット（`HEAD`）です。sekai には git のインデックスが存在しないため、インデックスの代わりに HEAD がデフォルトの復元元になります。HEAD が未生成（コミットが 1 つもない）の場合は `no commit selected` で失敗します。

## 書き込まれる内容

デフォルトは git restore の no-overlay モードに従います：

- 選択範囲内にある、ソースコミットに含まれない（コミット以降に作成された）リージョンファイルは、ソースと完全に一致させるため削除されます。
- 再構築されるファイルはソースコミットのチャンクのみで構成されます。ソースコミット以降に追加されたチャンクは破棄され、ツームストーンが記録されたチャンクは削除されます（全チャンクがツームストーンのリージョンはファイル自体が削除されます）。
- CAS 内に存在しない Blob がある場合は、チェックアウトと同様にエラーを報告して即座に中断します。

これらの挙動は、以下のオプションでカスタマイズできます：

| フラグ | 効果 |
|---|---|
| `--overlay` | ソースコミットに含まれないファイルを削除せず保持する（git の overlay モード）。再構築されるファイルの内容がソースのチャンクのみになる点は変わらない |
| `--on-missing-blob skip-chunk` | Blob が欠損しているチャンクをスキップして処理を継続する（デフォルトは `abort`） |
| `--on-missing-file derived-only\|error` | 配置先を推測する代わりに、兄弟フォルダの探索を無視するか、エラーとして終了する（デフォルトは `sibling-first`） |

- `--jobs N`: 同時に再構築するファイル数を設定します（`0` を指定すると CPU コア数と同じ数になります）。
- 通常通り `--timing` / `--json` / `--progress` と組み合わせられます。JSON ペイロードは `restore` エンベロープの中身がチェックアウトと同じ形式です（[自動化](../automation.md)を参照）。
- 再構築の開始前に、CLI は復元元・スコープ・ポリシーの設定内容を標準エラー出力に表示します（通常テキスト出力時のみ）。

チェックアウトと同様に、実行前にサーバーの書き込みを停止してください。詳細は[サーバー連携](../server-coordination.md)を参照してください。
