# 検証・検査

以下のコマンドは、ワールドやストアに対して書き込みを一切行いません。

```sh
sekai --store ./sekai-store list
sekai --store ./sekai-store status ./world
sekai --store ./sekai-store diff 1 2 --in overworld:0,0
sekai debug scan ./world
```

- `list`: スナップショットを古い順に表示します。日時は Unix ミリ秒タイムスタンプで保持されます（RFC 3339 形式の日時表示は通常テキスト出力時のみ）。各スナップショットに付与されているタグも併記されます（詳細は[タグ](tags.md)を参照）。`--stat` を指定すると、スナップショットごとの変更統計（fresh / tombstone / new-blob / effective の件数）も追加表示されます。ストアが空の場合は標準エラー出力に案内を表示し、終了コード 0 で正常終了します。
- `status`: バックアップを実行した場合に何が記録されるかをプレビューします。比較基準となるスナップショット（`latest`、ストアが空の場合は `null`）、変更のあったリージョン（新規追加・削除されたファイルを区別して表示）、新規に記録されるチャンク数、ツームストーン数、CAS に存在しない Blob などを報告します。`clean` は指定スコープ内が最新スナップショットと完全に一致していることを示し、その間にワールドが更新されない限り、直後に実行する `backup` の記録件数と完全に一致します。なお、`backup --dry-run` というオプションはあえて用意されておらず、この `status` コマンドがその役割を担います。`--jobs N` でプレビュー処理のワーカースレッド数（`0` は CPU コア数）を指定できます。
- `diff`: 2つのスナップショット間、または稼働中の実ワールド（`--world`）とスナップショット間のチャンク NBT を比較します。`--in DIM:x,z` で単一チャンクを指定した場合はそのチャンクの詳細な差分が出力されます。複数の範囲を指定した場合はグループ化された出力に切り替わり、差分のないチャンクは自動的に省略されます。スコープフラグ（`--in`, `--region`, `--kind`）で比較対象を指定できます（詳細は[スコープ（対象範囲）の選択](../scope.md)を参照）。比較対象の一方にチャンクが存在しないかツームストーンになっている場合は、空の NBT compound として扱って比較されます。存在しない座標を指定してもエラーにはなりません（[ADR-0006](https://github.com/tmcjapan/sekai/blob/main/docs/adr/0006-diff-missing-as-empty.md) を参照）。データが破損している場合や必要な Blob が欠損している場合のみエラーとなります。`--show-values` を指定すると、通常テキスト出力時に新旧の具体的な値を表示します。
- `debug scan`: 各リージョンファイルのファイルサイズ、mtime（最終更新日時）、チャンク数、ファイル全体のコンテンツハッシュを一覧表示します。`--timing` を付与するとフェーズごとの処理時間も確認できます。読み取りやパースに失敗したファイルは、単に無視されるのではなくスキップ理由とともに報告されるため、不完全なスキャン結果が完全な一覧であると誤認されるのを防ぎます。
