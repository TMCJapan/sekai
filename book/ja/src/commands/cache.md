# キャッシュ

```sh
sekai cache clean
sekai cache update --world ./world
```

`cache` はリージョンイメージキャッシュを管理するコマンドです。キャッシュはストア内の高速化専用キースペース（`meta.sqlite` や `blobs/` と並ぶ `cache/`）で、リージョンノードハッシュごとに、その元となった未展開の `.mca` イメージを保持します。これにより、`diff` と `status` のプレビューは、チャンクを1つも解凍・正規化することなく、完全にカバーされたリージョンが不変であることを証明できます（[基本概念](../concepts.md)を参照）。

キャッシュは派生データであり、履歴そのものではありません。すべてのエントリはワールドとスナップショットツリーから再計算できます。

- `cache clean` はキャッシュされたすべてのエントリを削除し、削除件数を表示します:

  ```text
  cleared 12 cached region image(s)
  ```

  いつ実行しても安全です。削除してもコミットやチェックアウトが読み書きする内容は一切変わらず、次のコミットが必要なエントリを再構築するまでの間、パフォーマンスが低下するだけです。空のキャッシュに対して再実行すると `0` が表示されます（冪等な操作です）。
- `cache update` はライブワールドのリージョンファイルをハッシュし、コミットを記録せずにキャッシュを構築します:

  ```text
  cached 3 new region image(s), 1 already present, 0 empty (4 files, 101 chunks)
  ```

  コミットとまったく同じようにすべてのチャンクを読み込んでハッシュしますが、書き込むのはキャッシュエントリだけです。Blob もメタデータもコミットも書き込みません。`cache clean` の後や最初のコミットの前にキャッシュを温め、`diff` と `status` がすぐに変更不要リージョンを証明できるようにするために使います。`--world` のデフォルトはカレントディレクトリです。`--jobs` はハッシュ処理のワーカー数を指定します（`0` は CPU ごとに1つ）。ワールド全体をハッシュするため、破損したチャンクや未対応のチャンクがあると実行は明確に失敗します。すでに書き込まれたエントリはそのまま残ります。
- 容量削減には `clean` を使用します。コミットと Blob は追記専用で削除されることはないため、ストア内で縮小できるのはキャッシュだけです。[二次バックアップ](../store.md)の前に削除しておくとコピーを小さく保てます。復元したストアは、次のコミット（または `cache update`）までキャッシュが冷えた状態で動作するだけです。
- ストアは事前に作成しておく必要があります。先に `sekai init` を実行してください（[ストアの場所](../store.md)を参照）。ストアが存在しない場合、何も作成せずに失敗します。
- `--json` を指定すると、`clean` は削除件数を `entries` として、`update` は `files`/`chunks`/`entries`/`existing`/`empty` を出力します。ペイロードの完全な仕様は [docs/json.md](https://github.com/tmcjapan/sekai/blob/main/docs/json.md) を参照してください。`update` は `--timing` と `--progress` に対応しています。`clean` には計測するフェーズやカウントする項目がないため、どちらも利用できません。
