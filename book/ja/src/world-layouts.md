# ワールドレイアウト

`.mca` フォーマット自体は共通ですが、サーバーの種類ごとにディレクトリ配置（レイアウト）は異なります。sekai は指定されたパスを1回の検知ステップで分類し、*ディメンションマップ*（観測されたディメンションごとのディレクトリ一覧）に変換します。以降の処理（バックアップ、ロールバック、diff、エクスポート）はすべてこのマップに基づいて動作します。実行時は常に同じ対象パスを指定してください。

## レイアウトの種類

- **バニラ (Vanilla)**: 1つのワールドディレクトリを指定します（中に `region/`, `DIM-1/`, `DIM1/`、または 26.1 以降では `dimensions/minecraft/<name>/` が存在するディレクトリ）。
- **Bukkit 系**（Bukkit / Spigot / Paper / Purpur の 26.1 より前のレイアウト）: サーバールートディレクトリを指定します。`<base>/`, `<base>_nether/DIM-1/`, `<base>_the_end/DIM1/` が配置されています（ここで `<base>` は `level-name` の値で、デフォルトは `world` です）。データパックのカスタムディメンション `<namespace>:<path>` は、それぞれ専用の `<base>_<namespace>_<path>/dimensions/<namespace>/<path>/` に格納されます。※ Paper 26.1+ ではバニラレイアウトへ移行します。
- **プラグインワールド**（Multiverse 等）: ファイル内容に基づいて自動検出される任意のフォルダ。

## 検知の流れ

ワールドを開く際、ルートは一度だけ分類されます。

1. ルートに `server.properties` があれば読み込み、コメントアウトされていない最初の `level-name=` 行を採用します（値は前後の空白を除去）。ファイルがない・読めない場合や、値が空または単一の通常のディレクトリ名でない場合（区切り文字や `.`/`..` を含むなど）は「指定なし」として扱い、壊れたファイルが観測ルートの外へレイアウトを向けることはありません。
2. `region/`, `entities/`, `poi/` のいずれかに解析可能な `r.<x>.<z>.mca` ファイルが1つ以上あるディレクトリを「ワールドディレクトリ」と判定します。
3. 候補は以下の順でチェックされ、最初に一致したレイアウトが採用されます：

```text
level-name が見つかった?
  ├─ <base>/dimensions/minecraft/<name>/ はワールドディレクトリ?  → Bukkit（26.1 レイアウト）
  └─ <base>/, <base>_nether/DIM-1, <base>_the_end/DIM1?          → Bukkit（分割レイアウト）
dimensions/minecraft/<name>/ はワールドディレクトリ?              → バニラ（26.1 レイアウト）
region/, DIM-1/, DIM1/ はワールドディレクトリ?                     → バニラ（旧レイアウト）
いずれにも一致しない                                              → 空の旧レイアウト
```

一致するのは最初のレイアウトのみです。別レイアウトの残骸（例: 26.1 の `dimensions/` ツリーの隣に残った旧フォルダ）は探索対象から外れます。どのレイアウトにも一致しないルートは空の旧レイアウトのワールド（エクスポートの出力先など）として扱われますが、存在しないルートを探索しようとした場合はエラーになります。

## ディメンションマップ（収集）

検知でレイアウトが決まると、観測されたディメンションごとにディレクトリを1つ解決します：

```text
Bukkit（26.1）    <base>/dimensions/ 配下の <namespace>/<name> すべて
Bukkit（分割）     <base>/（オーバーワールド）, <base>_nether/DIM-1, <base>_the_end/DIM1
                  + 各兄弟フォルダ内の dimensions/ ツリー配下の <namespace>/<name> すべて
バニラ（26.1）     dimensions/ 配下の <namespace>/<name> すべて
バニラ（旧）       region/（オーバーワールド）, DIM-1, DIM1
                  + dimensions/<namespace>/<name>（存在する場合。移行前のデータパック）
```

- 分割レイアウトの兄弟フォルダ名は曖昧です（`<namespace>` と `<path>` の両方に `_` を含められます）。そのためデータパックディメンションの同一性は、フォルダ名ではなく内部の `dimensions/` ツリーから判定します。
- 空のディメンションディレクトリもマップに残ります（最初のリージョンファイルが現れる前でも保持されます）。
- 各ディメンションには、正規キー `<namespace>:<name>` の安定したハッシュ ID が割り当てられます。バニラの3種はファイルの場所によらず常に `minecraft:overworld`, `minecraft:the_nether`, `minecraft:the_end` を使うため、レイアウト間の移行（例: Paper 26.1 で分割レイアウトが `dimensions/` に統合される場合）でも同じ ID、つまり連続した履歴を保てます。ワールドフォルダ（外側）の名前を変えても ID は変わりませんが、ディメンションディレクトリ（またはネームスペース）の名前を変えると、そのディメンションの履歴は新しく始まります。

## 探索

マップ上の各ディメンションについて、3つのリージョン種別を走査し、バックアップやロールバックが扱うファイルを列挙します：

```text
ディメンションディレクトリ ─▶ region/ entities/ poi/
  ─▶ 名前順にソート
  ─▶ r.<x>.<z>.mca のみ採用、同一座標は名前順で先のファイルが勝つ
  ─▶ RegionRef { path, id, kind, x, z }
```

- 同一座標の表記ゆれ（`r.0.0.mca` と `r.00.00.mca`）は、名前順で常に同じ解決結果になります。
- シンボリックリンクはゲームと同様に追跡します。種別ディレクトリが存在しない場合は「空」として扱いますが、ワールドルート自体が見つからない場合や読み取れないディレクトリがある場合は、ディメンションを黙って落とさずエラーとして通知します。
- ロールバックとエクスポートはマップから出力先パスを導出します。バックアップ後にフォルダが移動していた場合、欠落したリージョンファイルは同一ディメンションの生存している兄弟ファイルの隣に復元されます。観測された場所が一切ない場合は、誤った場所に書き込む代わりにエラー（`UnknownRegionPath`）で安全に中断します。

アーキテクチャ全体の概要は [ARCHITECTURE.md](https://github.com/tmcjapan/sekai/blob/main/ARCHITECTURE.md) の「World Layouts」を参照してください。
