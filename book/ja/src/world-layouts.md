# ワールドレイアウト

`.mca` フォーマット自体は共通ですが、サーバーの種類ごとにディレクトリ配置（レイアウト）は異なります。実行時は常に同じ対象パスを指定してください：

- **バニラ 26.1+**: `dimensions/minecraft/<name>/` を含む単一のワールドディレクトリ。
- **バニラ レガシー**: 単一のワールドディレクトリ（`region/`, `DIM-1/`, `DIM1/`）。
- **Bukkit 26.1+（Paper）**: サーバールートディレクトリ。`<base>/` フォルダの中に `dimensions/minecraft/<name>/` が配置されています（`<base>` は `level-name` の値で、デフォルトは `world`）。
- **Bukkit レガシー**（Bukkit / Spigot / Paper / Purpur の 26.1 より前のレイアウト）: サーバールートディレクトリ。`<base>/`, `<base>_nether/DIM-1/`, `<base>_the_end/DIM1/` が配置されています。
- **プラグインワールド**（Multiverse 等）: 選択されたワールドの隣にある任意のワールドフォルダ。ファイル内容に基づいて自動検出されます。

パスを開くとレイアウトが1つだけ（狭いシグネチャを優先して）検出され、そのレイアウトのファイルのみが走査されます。他のレイアウトの残骸（移行時の残りや stray な `dimensions/` ツリー）は統合されず無視されます。データパックのディメンションはどのレイアウトでもワールド直下の `dimensions/<ns>/<name>` にあり、プラグインワールドはそれぞれ自身のレイアウトを1つ検出します。

ネームスペースに関する完全な命名規則は [ARCHITECTURE.md](https://github.com/tmcjapan/sekai/blob/main/ARCHITECTURE.md) の「World Layouts」セクションを参照してください。

運用上の実用的な注意点は以下の2点です：

1. カスタムディメンションのフォルダ名はコンテンツハッシュに含まれるため、フォルダ名を変更すると過去のスナップショット履歴が孤立（リンク切れ）します。
2. フォルダが移動されていた場合、ロールバックは検出された兄弟フォルダ（同階層のフォルダ構造）を手がかりに可能な限り移動先を解決して復元します。ただし、誤った場所に書き込むリスクを避けるため、復元先が特定できない場合はエラー（`UnknownRegionPath`）を出して安全に中断します。
