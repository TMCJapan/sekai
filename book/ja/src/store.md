# ストアの場所

デフォルトでは `sekai` はカレントディレクトリの `.sekai` という
ディレクトリをストアとして使用します。この場合、すべてのコマンド
から `--store` を省略できます:

```sh
sekai init
sekai commit ./world
sekai log
```

ストアを別の場所に置きたい場合のみ `--store` を指定します:

```sh
sekai --store ./backups/sekai init
sekai --store ./backups/sekai commit ./world
```

`--store` はグローバルオプションで、すべてのサブコマンドで使用
できます。

## ストアの初期化

ストアを作成できるのは `sekai init` だけです。他のコマンドより
先に一度実行してください。それ以外のすべてのコマンド（`commit`
を含む）は、ストアが存在しない場合に失敗し、先に `sekai init` を
実行するよう促します。

`git init` と同様に、既存のストアに対して `init` を再実行しても
安全です。再初期化された旨が表示され、記録済みの履歴には一切
変更が加わりません。

## ストア設定

`sekai config` は `<store>/config.toml` にストア設定を読み書き
します。リポジトリスコープに限定した `git config` に相当し、
グローバル設定は存在しません。最初の設定項目はコミット作者名
です:

```sh
sekai config user.name "Alice"   # 設定
sekai config user.name           # 読み取り（値のみ出力）
sekai config --list              # 設定済みキーを key=value で一覧
sekai config user.name --unset   # 削除
```

キー名の大文字小文字は区別されません。未設定のキーは終了コード 1
で失敗しますが、`--default <value>` でフォールバック値を指定でき
ます。他のコマンドと同様に `config` はストアを排他的にオープン
するため、別のプロセスがストアを保持している間（バックアップ
実行中など）は使用できません。ストアリンクは実際のストアルート
に解決されます。`--json` は標準のエンベロープを出力します
（`docs/json.md` 参照）。

## ワークツリー

1つのストアは複数のワールドをバックアップでき、それぞれはストアを開く
場所ごとのワークツリーとして登録されます。ストア自身（メイン）の
ワークツリーはストアのルートディレクトリ、リンクされたワークツリーは
ストアリンクファイルがその場所です。ストアのルートは、書き方が違っても
メインのワークツリーを開きます。ストアを移動・コピーしても、メインの
ワークツリーはそのまま使えます。リンクされたワークツリーはストアの
履歴・Blob・キャッシュを共有します。一覧表示と削除の方法は
[ワークツリー](commands/worktree.md)を参照してください。

## 二次バックアップ

コミット、メタデータ、Blob、リージョンイメージキャッシュなど、ストア全体を含む完全な二次バックアップを作成したい場合は、ストアディレクトリ全体をそのまま外部ストレージ等へコピーまたはアーカイブしてください。ストアへの書き込みはクラッシュに強い順序（参照するメタデータのコミットより先に CAS Blob をフラッシュ）で行われるため、コピーされたストアでもデータの一貫性が保たれます。[キャッシュ](commands/cache.md)は派生データであり再構築可能なので、バックアップに含めなくても次回実行時のパフォーマンスが低下するだけです。
