# ストアの場所

Git のリポジトリが `.git` に置かれるのと同じように、ワールドのストアはワールドのルートに `.sekai` として置かれます。コマンドはワールド内のどこからでも実行できます。sekai はカレントディレクトリから親へたどり、最初に見つけた `.sekai` からストアとワークツリーを決めます。

```sh
cd ./world
sekai init
sekai commit
sekai log
```

探し方は、次の2つのグローバルオプションで変えられます。

- `--world <dir>`: カレントディレクトリの代わりに `<dir>` から探し始めます。
- `--store <dir>`: 別のストアを使います。`init` と組み合わせると、ワールドはそのストアのリンクされたワークツリーになり、`init` はストアを指す `.sekai` リンクファイルを書き込みます。以後のコマンドは、ワールドだけからストアを見つけられます。

```sh
sekai --world ./world --store ./backups/sekai init
sekai --world ./world commit
```

1つのワールドが属するストアは1つだけです。`.sekai` が別のストアを指しているワールドに対して、`init` は失敗します。どのワールドの中でもない場所でも、`--store` を指定すれば、`log --all`、`branch`、`tag`、`scope`、`worktree list` のようにワールドを必要としないコマンドは実行できます。

## ストアの初期化

ストアを作成できるコマンドは `sekai init` だけです。他のコマンドより先に、ワールドで一度だけ実行してください。他のコマンドはストアが存在しない場合に失敗し、先に `sekai init` を実行するよう案内します。

`git init` と同様に、`init` を再実行しても安全です。再初期化であることを表示し、記録済みの履歴には手を加えません。HEAD は `main` 上の未作成（unborn）の状態で始まり、最初のコミットでブランチが作られます。

## 二次バックアップ

コミット、メタデータ、Blob、リージョンイメージキャッシュを含むすべてのデータを完全にバックアップするには、ストアのディレクトリ全体を外部の場所にコピーまたはアーカイブしてください。ストアへの書き込みはクラッシュ時の整合性を保つ順序で行われる（CAS の Blob は、それを参照するメタデータのコミットより先にフラッシュされる）ため、コピーしたストアは自己整合しています。[キャッシュ](commands/cache.md)は派生データで再構築できるため、バックアップから除外しても、次回実行時のパフォーマンスが低下するだけです。
