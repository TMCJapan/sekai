# 基本概念

- **コミット (Commit)**: 記録された1つのワールド状態であり、親・作成時刻・差分に対する Blake3 の内容アドレス型ハッシュで識別されます（`log` ではストアのローカルな記録順で古い順に表示されます）。同一のコミットを再度記録しても行は重複しません。コミットは新規に変更・追加された行（レコード）のみを保存します。読み取り時は過去のコミットへのフォールバックを通じて実効状態を解決するため、メタデータの増加量はワールド全体のサイズではなく、発生した変更量に比例します。
- **Ref**: コミットを指す名前付きの可変ポインタ（sekai のブランチ）です。active な ref が1つあり、新規コミットはそこからぶら下がります。active な ref を切り替えると履歴が分岐します（[Ref](commands/refs.md) を参照）。
- **チャンクハッシュ（CAS キー）**: 解凍済みチャンクを正規化したダイジェストです。`LastUpdate` などの揮発性タグを除外した正規形に対して計算されるため、チャンクのトップレベルのキーの順序や圧縮コーデックに依存しません。sekai が読まないキーはハッシュに影響しません。`entities`/`poi` は level chunk のスキーマを持たないため、ペイロードのバイト列そのものをキーにします。同一内容はすべてのコミット間で単一のコピーとして共有され、チェックアウト時はキャプチャしたバイト列をそのまま復元するため、揮発性タグもコミット取得時点の値に巻き戻されます。
- **差分専用ハッシュはありません**: `diff` はコミット時に記録された同じダイジェストを履歴から読み出して比較します。チャンクとして扱うのは整形済みの NBT のみです。`region/` のペイロードは level chunk としてデコードできる必要があり、`entities`/`poi` のペイロードは整形済みの NBT である必要があります。正規化できないペイロードにはキーが与えられず、バイト列の同一性で保存されることなくインジェストが失敗します。
- **ツームストーン (Tombstone / 削除レコード)**: チャンクが存在しないことを明示的に表すレコードです。あるコミットから次のコミットまでの間に削除されたチャンクは、単に記録から消す（サイレントにする）のではなくツームストーンとして記録されます。これにより、チェックアウト時にそのチャンクを確実に再削除できます。
- **導出状態テーブルなし**: リージョンのフィンガープリントは永続化されません。各コミットはスコープ内のファイルを毎回読み直し、Blob が変化したチャンクの行だけを書き込みます。再構築すべきキャッシュがないため、履歴は常に正しい状態を保ちます。

正式な仕様や定義については、[ARCHITECTURE.md](https://github.com/tmcjapan/sekai/blob/main/ARCHITECTURE.md)（「Data & Hashing Model」および「History, State, and GC Model」）を参照してください。
